# 年菜 GAS 設定步驟（測試環境）

這支 GAS 綁在**當年度的年菜訂單試算表**上，表單跟著試算表一起複製。這次先做測試檔，**不要動 2026 正式檔**。

## 這支 GAS 做什麼

| 檔案 | 內容 |
|---|---|
| `Config.gs` | 共用設定（分頁名稱、店家信箱、時間戳記格式） |
| `Settings.gs` | 「設定」分頁讀寫（品項唯一來源是 WebPOS） |
| `Responses.gs` | 「表單回應」依**題目名稱**對應欄位，不用欄位編號 |
| `Sellout.gs` | 需求計算（套餐拆成單品）、停售檢查（達上限自動關閉表單並寄信通知） |
| `WebposSubmit.gs` | WebPOS 現場單用 FormApp 送進表單（「現結＋流水號」防重複；表單關閉時暫時開啟→送出→關閉） |
| `Confirm.gs` | 表單提交時寄確認信（用 `e.range` 讀那一列）＋停售檢查 |
| `Api.gs` | 網頁應用程式入口：doPost（送單、同步設定、製作完成）、doGet（需求查詢） |
| `Menu.gs` | 「年菜工具」選單：初始化、設定密鑰、同步到表單、檢查停售、重新套用保護範圍 |
| `Protect.gs` | 保護範圍（見下）＋匯款資訊被修改時寄信通知 |
| `ConfirmPickup.html`、`ConfirmDelivery.html` | 確認信範本（2026 年視覺與文案，改成 `data.items` 迴圈，年份、日期從「設定」帶入） |
| `appsscript.json` | 時區 Asia/Taipei、網頁應用程式設定 |

**匯款資訊不在程式裡**：確認信的戶名／銀行名稱／分行名稱／匯款帳號改讀「設定」分頁的「匯款戶名」「匯款銀行」「匯款分行」「匯款帳號」，預設空白（空白時信裡那幾格就是空的）。

**保護範圍**（初始化時自動設定，之後可用「年菜工具 → 重新套用保護範圍」重建）：

| 範圍 | 保護方式 |
|---|---|
| 「設定」匯款戶名／銀行／分行／帳號 | 鎖定，只有擁有者（你）能改；**任何人修改都會寄信通知店家信箱** |
| 「表單回應」整個分頁 | 修改前跳警告，確認後才能改（手動改數量、取消訂單照常可以做） |
| 「設定」品項表（D～J 欄） | 修改前跳警告（品項應由 WebPOS 同步） |

表單送出、GAS 自己寫入（寄信狀態、WebPOS 同步）不受影響。另外請把試算表只共用給必要的人，不要開「知道連結的人都能檢視」（表單回應裡有客人個資）。

確認信寄送規則：
- 客人有填 email → 寄給客人，bcc 店家
- 表單 email 是店家信箱（現場單客人沒填）→ 只寄給店家，用來確認訂單有進 Sheet

## 步驟

### 1. 複製測試檔
1. 在 Google 雲端硬碟建一個測試資料夾（例如「年菜 2027 測試」）。
2. 打開 2026 年菜訂單試算表 →「檔案 → 建立副本」，存到測試資料夾，命名「2027 年菜訂單（測試）」。
   Google 會**一起複製連結的表單**（副本表單會出現在同一個資料夾）。
3. 打開副本試算表，確認：
   - 回應分頁名稱是 **「表單回應」**（不是的話改名）
   - 選單「表單」→「前往即時表單」打得開，而且是**副本表單**，不是 2026 正式表單
4. 清掉副本裡的 2026 回應（不然會算進需求，而且燉羊肉等舊品項對不到）：
   副本表單 →「回應」→ ⋮ →「刪除所有回應」，再把試算表「表單回應」分頁第 2 列以下的內容清除。

### 2. 貼上 GAS
1. 副本試算表 →「擴充功能 → Apps Script」。
2. 刪掉原本的程式（舊的 confirm.gs 等）。
3. 依上表建立同名檔案，把 `~/webpos-dev/gas/nianfai/` 裡每個檔案的內容貼進去：
   - `.gs` 檔：「＋ → 指令碼」，名稱不用打 `.gs`
   - `.html` 檔：「＋ → HTML」，名稱用 `ConfirmPickup`、`ConfirmDelivery`
4. 專案設定（齒輪）→ 勾選「在編輯器中顯示 appsscript.json」，把 `appsscript.json` 內容貼進去。
5. 儲存。

### 3. 初始化與授權（要你本人操作）
1. 回到試算表，重新整理，上方會出現「年菜工具」選單。
2. 「年菜工具 → 初始化（安裝觸發條件）」→ 依指示授權（Google 會提醒「未經驗證的應用程式」，選「進階 → 前往」）。
   初始化會建立「設定」分頁（含空白的匯款戶名／銀行／分行／帳號四列）並一併設定保護範圍。
   接著到「設定」填匯款資訊——只有你能改，填完會收到「匯款資訊被修改」的通知信，這是正常的，代表通知有作用。
   之後如果自己新增或搬動了匯款欄位，按「年菜工具 → 重新套用保護範圍」。
3. 「年菜工具 → 設定 WebPOS 密鑰」→ 貼上 `~/webpos-dev/.env.dev` 裡 `NIANFAI_GAS_SECRET=` 後面那一串。

### 4. 部署網頁應用程式
1. Apps Script →「部署 → 新增部署作業」→ 類型選「網頁應用程式」。
2. 執行身分：**我**；存取權：**所有人**（密鑰驗證由程式處理）。
3. 部署後複製網址（結尾是 `/exec`），填進 `~/webpos-dev/.env.dev` 的 `NIANFAI_GAS_URL=`，或直接給 Claude。
4. 之後改了程式要「部署 → 管理部署作業 → 編輯 → 版本選新版本」，網址不變。

### 5. 同步品項與表單
1. WebPOS 年菜管理頁「4. Google 表單／Sheet」→ 確認顯示「已連線」→「同步品項到 Sheet」。
2. 試算表「設定」分頁檢查品項、價格、套餐組成、取貨日、寄出期間、最後取貨日（取貨與寄出日期在 WebPOS 年菜管理頁「2. 取貨與寄出日期」設定，同步時一起寫入）；自己補「祝賀語」「匯款戶名／銀行／分行／帳號」。
3. 「年菜工具 → 同步到表單」→ 看差異 → 確定。
   - 套餐題目會改成「品名 (價格元)」，也就是「富貴套餐 (3500元)」，題目說明文字不會動。
   - 單點表格的列會改成 2027 年品項，平常也賣的前面加 `*`。
   - 取貨日改成 2027/1/29 (五) ～ 2027/2/4 (四)。
4. 說明文字、圖片、須知裡的日期（截止日、寄出日）請自己手動更新。

### 6. 圖片要自己處理（提醒）
- **表單**：須知、套餐、單點頁的宣傳圖（2026 年的圖寫著燉羊肉、1/14 截止），請上傳 2027 年的圖片。
- **確認信嵌圖**：範本裡的 Logo、LINE 圖示是 2026 年用 email 編輯器（BeePro）產生時放在對方圖床上的網址（`imgdist.com`、`getbee.io`）。之後若要換圖或擔心圖床失效，把圖片放到自己可公開存取的位置，再替換 `ConfirmPickup.html`、`ConfirmDelivery.html` 裡的 `<img src="...">` 網址。
- **匯款資訊**：如果想用圖片（例如帳號截圖）取代文字，一樣上傳後把網址換進範本「匯款資訊」那一段；用文字的話填「設定」分頁即可。

## 測試時要確認的（handoff 第 12 節）
- WebPOS 現場單補資料送出 → 表單回應多一列、末五碼是「現結27001」、品項數量正確
- 同一張重送不會變兩列
- 表單關閉時，WebPOS 仍能送單（暫時開啟→送出→關閉）
- FormApp 送出時是否強制檢查必填題
- 確認信：自取／宅配兩種範本、時間戳記格式、套餐組成（花雕雞）、收件人與 bcc 規則
- 按「製作完成」或新訂單達上限 → 表單自動關閉、收到通知信、WebPOS 顯示表單已關閉
- WebPOS 年菜庫存的需求＝Sheet 總量＋未送出的現場單，不重複
