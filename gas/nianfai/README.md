# 咕咕義年菜系統 GAS

一支**獨立的** Apps Script 專案（不綁在任何試算表上），**只需要部署、授權一次**。
之後每年在 WebPOS 年菜管理頁按「建立 Google 試算表與表單」，由這支 GAS 自動建立當年度的：

- 試算表：宅配、自取、查詢、統計、備料表、修改紀錄、設定、表單回應
- 預購表單（結構與文案沿用 2026 年，只替換年份、日期、價格、套餐組成），已連到試算表
- 保護範圍、觸發條件（提交表單時寄確認信與檢查停售；編輯時記錄修改、匯款資訊異動通知）

**不需要複製去年的試算表或表單。**

## 檔案

| 檔案 | 內容 |
|---|---|
| `Config.gs` | 共用設定、依環境＋年度切換檔案、授權用的 `nfAuthorize` |
| `Api.gs` | 網頁應用程式入口（WebPOS 呼叫）：建立年度、同步、檢查、送單、需求查詢 |
| `FormBuild.gs` | 建立試算表＋表單＋各分頁＋保護範圍＋觸發條件；表單文案 |
| `OrderSheets.gs` | 「宅配」「自取」：GAS 依表單回應寫入，手動欄跟著訂單編號保存、取消列保留、改到非手動欄自動還原 |
| `Tabs.gs` | 查詢、統計、備料表、修改紀錄的公式與格式 |
| `Menu.gs` | 試算表「📧 年菜寄信」選單的動作（試算表的小程式透過程式庫 NianfaiLib 呼叫） |
| `Mail.gs` | 寄出前確認、出貨通知、取貨提醒（每天 08:00 自動）；寄信狀態存在指令碼屬性 |
| `Settings.gs` | 「設定」分頁讀寫（品項唯一來源是 WebPOS） |
| `Responses.gs` | 「表單回應」對應：優先用建立表單時記下的題目 ID，再用題目名稱 |
| `FormSync.gs` | 同步到表單（先列差異再套用）、檢查表單對應 |
| `WebposSubmit.gs` | WebPOS 現場單用 FormApp 送進表單（「現結＋流水號」防重複；表單關閉時暫時開啟→送出→關閉） |
| `Confirm.gs` | 表單提交時寄確認信＋停售檢查 |
| `Sellout.gs` | 需求計算（套餐拆成單品）、達上限自動關閉表單並寄信通知 |
| `Protect.gs` | 保護範圍、修改紀錄、匯款資訊異動通知 |
| `ConfirmPickup.html`、`ConfirmDelivery.html`、`PreShip.html`、`Shipped.html`、`PickupReminder.html` | 確認信、寄出前確認、出貨通知、取貨提醒範本：由 `gas/tools/build_email_templates.py` 產生，統一 2026 年出貨通知樣式、沿用 2026 年文案 |
| `appsscript.json` | 時區、網頁應用程式設定 |

測試工具（不用貼到 Apps Script）：`gas/tools/gas_mock_test.js`（模擬 Google 服務跑主要流程）、
`gas_mock_server.js`（本機假 GAS 伺服器）、`deploy_gas.sh`（用 clasp 上傳並更新現用部署，網址不變）、`setup_sheet_menu.sh`（在年度試算表裝「📧 年菜寄信」選單，每年一次；程式在 `gas/sheet-menu/`）、`build_email_templates.py`（產生 5 封信的 HTML 範本，統一 2026 年出貨通知樣式）。

## 第一次設定（只做一次；測試與正式各建一個專案）

1. 打開 https://script.google.com →「新專案」，命名「咕咕義年菜系統（測試）」。
2. 依上表建立同名檔案，把 `~/webpos-dev/gas/nianfai/` 每個檔案的內容貼進去：
   - `.gs`：「＋ → 指令碼」（名稱不用打 `.gs`，預設的 `程式碼.gs` 可以刪掉）
   - `.html`：「＋ → HTML」，名稱 `ConfirmPickup`、`ConfirmDelivery`、`PreShip`、`Shipped`、`PickupReminder`
   - 專案設定（齒輪）→ 勾選「在編輯器中顯示 appsscript.json」→ 貼上 `appsscript.json`
3. 上方函式選單選 `nfAuthorize` →「執行」→ 依指示授權（「未經驗證的應用程式」選「進階 → 前往」）。
4. 專案設定 →「指令碼屬性」→ 新增屬性 `WEBPOS_SECRET`，值貼上 `~/webpos-dev/.env.dev` 裡 `NIANFAI_GAS_SECRET=` 後面那一串。
5. 「部署 → 新增部署作業」→ 類型「網頁應用程式」→ 執行身分「我」、存取權「所有人」→ 部署。
6. 複製網址（結尾 `/exec`）給 Claude，或填進 `~/webpos-dev/.env.dev` 的 `NIANFAI_GAS_URL=`。

之後改了程式：「部署 → 管理部署作業 → 編輯 → 版本選新版本」，網址不變。

## 每年的流程（WebPOS 年菜管理頁）

1. **新年度初始化**（複製去年品項）
2. **取貨與寄出日期**：預購截止日、自取日、每日取貨時間、最後一天結束時間、宅配寄出日
3. **修正品項**（菜單管理）
4. **建立 Google 試算表與表單**（約 1 分鐘），放在雲端硬碟「咕咕義年菜（測試）」資料夾
5. **review 表單**（見下方「要自己處理的」）
6. **檢查表單對應** → 通過才能開賣
7. **開賣**

品項、價格、日期之後有變動：「同步品項到 Sheet」→「同步到表單」（先列出差異）→ 再「檢查表單對應」。

## 表單可以改什麼

**可以自由改（不影響對應）**：表單標題與說明、段落說明、題目下方的說明文字、圖片、主題顏色、確認訊息。

**不要改（對應依據）**：題目名稱（取貨方式、訂購人姓名、預計匯款帳號末五碼…）、選項（宅配／來店自取、取貨日、數量 1～8）、單點表格每一列的「品名 (價格元)」。
改到了「檢查表單對應」會列出哪裡對不上，開賣前一定會被擋下。

## 要自己處理的（建立後）

- **主題外觀**：頁首圖、顏色、字型（FormApp 不能設定）
- **文字格式**：說明欄只能放純文字，2026 年的粗體、斜體、底線要手動加
- **圖片**：宣傳圖直接在表單上加入（或把雲端硬碟圖片檔案 ID 填進「設定」的「套餐圖片ID」「單點圖片ID」，建立時自動插入）
- **匯款資訊段落**：2026 年列印版看不到原文，先用簡單說明，請改成你要的文字
- **表單問候語**：「設定」預設「…陪你迎接嶄新羊年！」，請確認用字（2026 年是「嶄金馬年」）
- **確認信嵌圖**：範本的 Logo、LINE 圖示是 2026 年 email 編輯器圖床（`imgdist.com`、`getbee.io`）的網址，要換圖或擔心失效，上傳到自己的位置再替換範本裡的 `<img src>`
- **匯款資訊**：填「設定」分頁「匯款戶名／匯款銀行／匯款分行／匯款帳號」（只有你能改，改了會收到通知信）；想用圖片的話，上傳後把網址換進範本「匯款資訊」那一段

## 保護範圍與通知（建立時自動設定，可從年菜管理頁「重新套用保護範圍」）

| 範圍 | 保護方式 |
|---|---|
| 「設定」匯款戶名／銀行／分行／帳號 | 只有擁有者能改；任何人修改都寄信通知 |
| 「表單回應」整個分頁 | 修改前跳警告（手動改數量、取消訂單照常可以做）；改了會上色、備註原值、「已修改」打勾、寫入「修改紀錄」 |
| 「設定」品項表 | 修改前跳警告（品項應由 WebPOS 同步） |

試算表請只共用給必要的人，不要開「知道連結的人都能檢視」（表單回應裡有客人個資）。

## 確認信寄送規則

- 客人有填 email → 寄給客人，bcc 店家
- 表單 email 是店家信箱（現場單客人沒填）→ 只寄給店家，用來確認訂單有進 Sheet

## 部署後要實測的（handoff 第 12 節）

- 建立試算表與表單：分頁、公式、表單分支（宅配／自取）、保護範圍、觸發條件
- 修改表單說明文字後「檢查表單對應」仍通過；改題目名稱會被擋下
- WebPOS 現場單送出 → 表單回應多一列、末五碼「現結27001」、品項數量正確；重送不會變兩列
- 表單關閉時 WebPOS 仍能送單；FormApp 送出是否強制檢查必填題
- 確認信：自取／宅配兩種範本、時間戳記、套餐組成、收件人與 bcc
- 製作完成／新訂單達上限 → 表單自動關閉、收到通知、WebPOS 顯示表單已關閉
- 手動修改表單回應 → 上色、備註、修改紀錄；修改匯款資訊 → 收到通知信
- 宅配／自取金額（含運費）、保冷袋與 2026 年算法一致；統計、備料表數字正確
